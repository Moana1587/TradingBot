# PM2 Setup Guide

This guide explains how to run the Copy Sniper Bot using PM2, a production process manager for Node.js applications.

## 📋 Prerequisites

1. **Install PM2 globally:**
   ```bash
   npm install -g pm2
   ```

2. **Build the project:**
   ```bash
   npm run build
   ```

3. **Configure your `.env` file:**
   Make sure your `.env` file is properly configured with all required variables.

## 🚀 Quick Start

### 1. Start the Bot
```bash
npm run pm2:start
```

This will:
- Start the bot using the PM2 ecosystem configuration
- Automatically restart on crashes
- Log output to `./logs/` directory
- Run in the background

### 2. Check Status
```bash
npm run pm2:status
```

Or use PM2 directly:
```bash
pm2 status
```

### 3. View Logs
```bash
npm run pm2:logs
```

Or view specific log files:
```bash
# Real-time logs
pm2 logs copy-sniper-bot

# Last 100 lines
pm2 logs copy-sniper-bot --lines 100

# Error logs only
pm2 logs copy-sniper-bot --err

# Output logs only
pm2 logs copy-sniper-bot --out
```

### 4. Stop the Bot
```bash
npm run pm2:stop
```

### 5. Restart the Bot
```bash
npm run pm2:restart
```

### 6. Delete from PM2
```bash
npm run pm2:delete
```

## 📝 Log Management

### Log Files Location
All logs are stored in the `./logs/` directory:
- `pm2-error.log` - Error logs
- `pm2-out.log` - Standard output logs
- `pm2-combined.log` - Combined logs

### Clear Logs
```bash
pm2 flush copy-sniper-bot
```

### Log Rotation
PM2 can automatically rotate logs. To enable:
```bash
pm2 install pm2-logrotate
pm2 set pm2-logrotate:max_size 10M
pm2 set pm2-logrotate:retain 7
```

## 🔄 Auto-Start on System Reboot

### Save Current PM2 Process List
```bash
npm run pm2:save
```

This saves your current PM2 process list.

### Setup Startup Script
```bash
pm2 startup
```

This will generate a command to run as root/admin. Copy and run that command.

**On Windows:**
PM2 doesn't support `pm2 startup` on Windows. Use alternative methods:
- Task Scheduler
- Windows Service (using `pm2-windows-startup` or `node-windows`)

**On Linux/Mac:**
```bash
# Run the command generated by pm2 startup
sudo env PATH=$PATH:/usr/bin pm2 startup systemd -u $USER --hp $HOME
```

### Restore Processes After Reboot
```bash
npm run pm2:resurrect
```

Or PM2 will automatically restore if startup script is configured.

## ⚙️ Configuration

The PM2 configuration is in `ecosystem.config.js`. Key settings:

```javascript
{
  name: 'copy-sniper-bot',        // Process name
  script: './dist/index.js',       // Entry point (must be built first)
  instances: 1,                     // Number of instances
  exec_mode: 'fork',               // Execution mode
  autorestart: true,                // Auto-restart on crash
  max_memory_restart: '500M',      // Restart if memory exceeds 500MB
  restart_delay: 4000,             // Wait 4s before restart
  max_restarts: 10,                // Max restarts in time window
  min_uptime: '10s',               // Min uptime to be considered stable
}
```

### Customize Configuration

Edit `ecosystem.config.js` to adjust:
- Memory limits
- Restart behavior
- Log file locations
- Environment variables

## 🐛 Troubleshooting

### Bot Not Starting

1. **Check if build is successful:**
   ```bash
   npm run build
   ```
   Ensure `dist/index.js` exists.

2. **Check environment variables:**
   ```bash
   # Verify .env file exists and is configured
   cat .env
   ```

3. **Check PM2 logs:**
   ```bash
   pm2 logs copy-sniper-bot --lines 50
   ```

4. **Check PM2 error logs:**
   ```bash
   tail -f logs/pm2-error.log
   ```

### Bot Keeps Restarting

1. **Check logs for errors:**
   ```bash
   pm2 logs copy-sniper-bot --err --lines 100
   ```

2. **Check memory usage:**
   ```bash
   pm2 monit
   ```
   If memory is high, increase `max_memory_restart` in `ecosystem.config.js`.

3. **Check restart count:**
   ```bash
   pm2 show copy-sniper-bot
   ```
   Look for "restart time" - if it's restarting too frequently, check logs.

### View Detailed Process Info
```bash
pm2 show copy-sniper-bot
```

This shows:
- Status
- Uptime
- Restart count
- Memory usage
- CPU usage
- Log file paths

### Reset Restart Count
If the bot has too many restarts and PM2 stops restarting it:
```bash
pm2 reset copy-sniper-bot
```

## 🔐 Security Notes

1. **Environment Variables:**
   - Never commit `.env` file
   - PM2 loads environment from `.env` automatically (via dotenv)
   - For production, consider using PM2's `env` section in ecosystem.config.js

2. **Log Files:**
   - Logs may contain sensitive information
   - Ensure `logs/` directory is in `.gitignore`
   - Rotate logs regularly

3. **Process Management:**
   - Only authorized users should have PM2 access
   - Use proper file permissions

## 🔄 Update Workflow

When updating the bot:

1. **Stop the bot:**
   ```bash
   npm run pm2:stop
   ```

2. **Pull latest code:**
   ```bash
   git pull
   ```

3. **Install dependencies (if needed):**
   ```bash
   npm install
   ```

4. **Rebuild:**
   ```bash
   npm run build
   ```

5. **Restart:**
   ```bash
   npm run pm2:restart
   ```

Or use a single command:
```bash
npm run pm2:stop && npm run build && npm run pm2:start
```
